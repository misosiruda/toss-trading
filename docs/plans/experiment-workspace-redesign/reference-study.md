# toss-trading 레이아웃 재설계 제안

2026-10-02 · paper-only UX · 구현/배포 전 설계안

## 추천

앱의 중심은 ‘실험 목록 → 설정 → 진행 → 결과·근거 → 비교·재실행’이다. MLflow/ClearML의 실행 구조를 골격으로 삼고 QuantConnect의 결과, TradingView의 리플레이, W&B의 비교 패턴을 조합한다.

## 확인한 공식 레퍼런스

1. [MLflow Search Runs](https://www.mlflow.org/docs/latest/ml/search/search-runs/): 좌측 실험 묶음, 중앙 실행 테이블, 상단 필터. 입력·버전·결과를 실행 단위에 결속하는 구조를 적용한다. 검색식을 먼저 알아야 하는 UX와 기술 열 과다는 제외한다
2. [ClearML Task Table](https://www.clear.ml/docs/latest/docs/webapp/webapp_exp_table/): 상태·시간·진행이 보이는 실행 목록. 목록 유지형 상세와 선택 실행 비교를 참고한다. 주요 행동을 아이콘만으로 표시하지 않는다
3. [QuantConnect Results](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/results): 큰 equity 차트, 아래 drawdown, 실행에 종속된 거래·로그·코드. 결과 상세의 구조로 적용하되 주요 지표는 3–4개로 압축한다
4. [TradingView Strategy Report](https://www.tradingview.com/support/solutions/43000764138-tradingview-strategy-report-how-to-start/): 시장 차트의 거래 표식과 하단 보고서. 시점별 거래·판단 근거 연결을 리플레이 탭에 적용한다. 양쪽 도구 모음이나 작은 하단 창에 모든 결과를 넣는 구성은 제외한다
5. [W&B Filter Runs](https://docs.coreweave.com/products/wandb/runs/filter-runs): 실행 목록의 필터·표시 개수와 우측 차트가 연결된 workspace. 비교 대상·기준 실행을 계속 보여주되 패널을 무제한 늘리는 방식은 제외한다

확인: 위 공식 문서의 실제 UI 이미지를 클라우드 브라우저로 시각 확인했다. 로그인 계정의 최신 앱을 조작한 것은 아니다. MLflow 예시는 2.8/2.10 화면이다. W&B 원래 문서는 공식 CoreWeave 문서로 이동했다. 이하 배치·모바일 동작은 관찰에 근거한 설계 제안이다.

이 문서는 레퍼런스에서 도출한 장기 목표다. 초기 구현 범위와 확인된 제한은
[현재 기획](product-plan.md)과 [기술 설계](technical-design.md)가 우선한다. 아래 저장 정책 실행,
단일 bucket 실제 실행, 검증 분할 입력, 서버 초안 저장은 초기 UX-03에서 지원하지 않는다.

## 정보구조

주내비는 ‘실험 / 전략·정책 / 비교 / 데이터’ 4개, 설정은 하단 utility로 둔다.

- 실험: 기본 진입점, 초안·진행·결과, 새 실험
- 전략·정책: 재사용·버전·bucket 배분·제약. 여러 실험의 공통 기준이므로 독립 메뉴
- 비교: 기준 실행과 후보의 결과 및 입력 차이
- 데이터: 시장·종목군·기간·출처·가용성·검증 분할
- 설정: provider/연결 상태·진단·전체 운영 감사

AI는 생성의 판단 방식과 상세의 근거로, risk는 생성의 제약과 상세의 차단 이유로, audit는 실행 기록으로, bucket은 정책 배분과 테스트 범위로 묶는다. 각각 독립 주메뉴를 만들지 않는다.

## 핵심 화면 1: 실험 목록

데스크톱: 왼쪽 208px 내비, 상단 제목과 오른쪽 ‘새 실험’. 진행/주의가 있을 때만 작은 상태 영역. 검색·상태·전략·데이터 필터 아래 실행 테이블이 본문의 대부분을 차지한다. 열은 이름, 상태, 정책 버전, 데이터·기간, 시작/소요 시간, 결과 요약. 진행 중에는 결과 대신 phase·처리 수·최근 갱신을 표시한다. 이름 클릭은 상세, 빠른 보기는 우측 360px drawer. 2개 이상 선택하면 비교 트레이가 나타난다.

모바일: 표를 이름·상태 / 정책·기간 / 결과·진행의 3줄 목록으로 전환한다. 필터는 sheet. 빠른 보기와 상세는 하나로 합친다. 뒤로 가도 필터·스크롤·비교 선택을 유지한다.

## 핵심 화면 2: 새 실험

데스크톱: 최대 1,180px 본문, 입력 7/12와 고정 요약 5/12의 2열. 3단계는 ‘전략·범위 → 데이터·실행 조건 → 검증·확인’이다.

1. 저장 정책 버전, 전체/단일 bucket, 지원 판단 모드
2. 실제시장/합성 fixture 구분, 종목군·기간·시간대, 검증 분할, 가상 자금·비용·sampling. 고급 항목은 접기
3. 통과/주의/차단, 입력 버전, 위험 제약, 실제 실행 지원 범위

요약에는 정책·bucket, 데이터, provider, 비용, 분할, 예상 산출물을 표시한다. 하단은 이전·검증·실제 동작을 정확히 말하는 생성 버튼이다.

모바일: 한 단계씩 한 열. 입력 요약은 sheet, 마지막 확인에는 핵심 값·경고를 본문에 펼친다. 오류에도 값과 단계 유지. 키보드가 하단 버튼을 가리지 않게 한다.

## 핵심 화면 3: 실행 워크스페이스

공통 헤더: 이름·ID·상태·시각, 정책 버전·bucket·기간·paper-only. 행동은 비교 추가와 조건 복제 후 새 실험이다.

실행 중: 증거가 있는 phase, 처리 수/총량, 경과 시간, 최근 heartbeat, 주요 사건. 총량이 없으면 가짜 백분율을 만들지 않는다. 갱신 지연을 성공·실패·생존으로 단정하지 않는다.

완료 후 4탭:

- 요약: 지표 3–4개, 큰 자산 변화+기준선, 같은 시간축의 낙폭, bucket별 결과·제약. 비용·표본·해석 한계는 근처
- 리플레이: 중앙 차트 65%, 선택 시점 inspector 35%. 하단 시간 선택·이전/다음 사건. 후보→AI 판단→Risk→모의 거래 연결
- 판단 근거: 사건 목록과 선택 상세. 이유 먼저, 입력·policy·Risk·결정·거래 참조를 펼침. AI 텍스트와 deterministic 검증 구분
- 기록: 입력·버전·출처·산출물·audit timeline. raw JSON은 마지막 펼침

모바일: 지표 2×2, 주 차트, 해석 제한, 근거 순서. 선택 시점 inspector는 전체 상세 또는 sheet. hover 대신 탭과 이전/다음 사건. 데스크톱 3열을 작은 크기로 축소하지 않는다.

## 비교 화면

기준 실행 1개와 후보 1–3개. 데이터 종류·기간·종목군·비용·정책/코드 버전 차이를 먼저 표시한다. 중간은 공통 축의 자산 변화·낙폭, 아래는 주요 지표와 ‘변경 입력만 보기’. 합성/실제시장, 단일 bucket/full portfolio, 서로 다른 기간을 무조건 같은 순위표로 섞지 않는다. 모바일은 기준+후보 1개의 차이부터 보고 후보를 전환한다.

## 실제 기능과 표시의 일치

프로젝트 dashboard README와 runbook에서 확인한 경계다. 레이아웃 변경으로 capability가 추가된 것처럼 표시하면 안 된다.

- bucket test 생성이 queued record 저장인 경로는 ‘테스트 대기 등록’으로 표시. 실제 runner 시작과 구분
- 현재 policy builder가 policy artifact를 runner에 적용하지 않고 검증 policyHash를 seed에 반영하는 경로에서는 ‘정책 적용 완료’ 표시 금지
- fixture 실험 runbook이 API/dashboard 미연결로 설명하는 경로는 실제 실행 가능한 화면처럼 노출하지 않음
- 미지원 취소·재개·자동 재시도·초안 저장을 가정하지 않음
- missing·stale·incomplete·실패·미지원·0을 분리하고 원본 실행을 재실행으로 덮지 않음

## 후보 판단과 완료 기준

실험 중심 A안은 현재 요청에 가장 적합하다. 차트 중심 B안은 리플레이 내부, 포트폴리오 중심 C안은 통합 운용 연결 이후 보조 화면으로 둔다.

이후 와이어프레임/구현 검증 기준:
- 첫 화면에서 새 실험·진행 상태 발견
- 설정→검증→생성→같은 실행 상세 연결
- 결과에서 거래 근거까지 2번 이내 선택
- 비교 조건 차이 및 비교 불가 이유 표시
- 1440px·1024px·390px에서 주요 여정과 상태 의미 유지
- 키보드·포커스·오류 설명·터치 동작 검증
- AI·policy·bucket·risk·audit 누락 없음

핵심 3화면의 [반응형 시안](wireframes.html)과 [기능별 구현 범위](pr-work-plan.md)로 이어진다.
시안은 합성 예시이며 production 기능 완료나 실행 결과가 아니다.
