## 해결할 문제

사용자는 현재 화면 구성이 불편하며, 여러 레퍼런스를 바탕으로 레이아웃을 다시 구성하기를 요청했다.
목표는 ‘실험 목록 → 조건 설정 → 실제 실행 → 결과와 근거 → 비교와 새 실행’이다.
화면을 카드 모음으로 바꾸는 것이 아니라 실행별 입력·진행·결과·근거를 한 장소에서 찾게 한다.

실험은 사용자가 이해하는 상위 명칭이다. 기존 `batchId`, `runId`, bucket `testId`,
fixture CLI `experimentId`를 같은 ID처럼 합치지 않는다. 처음 제공하는 실행 경로는 이미
runner가 연결된 historical paper simulation이다. fixture CLI EXP-01~04는 별도 도구이며
이번 첫 UI 연결과 혼동하지 않는다.

## 정보구조와 책임

| 주메뉴 | 우선 질문 | 내용 |
| --- | --- | --- |
| 실험 | 무엇을 실행했고 지금 어디까지 왔나? | 저장된 실행 목록, 3단계 생성, 실행 상세, 실패·미확인 상태 |
| 전략·정책 | 어떤 규칙을 보관하고 검증하나? | 정책 편집·검증·저장, bucket 준비 상태와 queued-only 테스트 등록 |
| 비교 | 조건과 결과가 무엇이 다른가? | 기준 1개 + 후보 최대 3개, 비교 가능성·입력 차이 우선 |
| 데이터 | 어떤 자료로 판단했나? | source·기간·coverage·split·가용성, 기존 validation 진입 |
| 설정 | 연결과 운영 상태를 어떻게 확인하나? | provider·진단·live readiness·전체 audit·component catalog |

설정은 sidebar 하단 utility다. AI·Risk·audit를 여러 주메뉴로 쪼개지 않고 실행별 근거에 연결한다.
전체 portfolio compliance와 전체 audit도 제거하지 않고 각각 전략·정책과 설정에 접근 경로를 둔다.
Legacy-only 자료는 이전이 끝날 때까지 연결 상태를 설명하는 호환 화면을 통해 접근한다.

## 핵심 화면과 행동

### 1. 실험 목록

데스크톱은 208px navigation, 명확한 제목과 ‘새 실험’, 한 줄 필터, 넓은 실행 테이블이다.
정상 상태에서 의미 없는 KPI 카드와 safety 카드를 반복하지 않는다. paper-only는 지속적인
작은 문구로 표시한다. 오류·진행·불완전 자료가 있을 때에만 관련 안내를 추가한다.

열: 실행 식별자/이름, 실행 상태, 실제 적용 설정, 자료·기간, 시작/종료, 관측된 결과 또는 진행.
전체 건수 API가 없으면 ‘불러온 N개’라고 쓴다. 클라이언트 필터를 서버 전체 검색처럼 표시하지 않는다.
이름 → 같은 ID의 상세. 목록 URL에 검색·필터·선택을 보존해 뒤로 가기에도 맥락을 유지한다.
선택 비교는 비교 기능이 검증된 PR에서만 활성화한다. 빠른 보기 drawer는 필수 동선 후에 추가한다.

모바일은 테이블을 3줄 목록으로 전환한다. 이름·상태 / 실제 설정·기간 / 결과·마지막 관측을
보이며 가로로 밀어야 주요 상태가 보이는 표는 사용하지 않는다. 상세·뒤로 가기의 경로가 같다.

### 2. 새 실험

3단계: ‘전략·범위 → 데이터·실행 조건 → 검증·확인’. 데스크톱은 입력 7/12 + 요약 5/12,
모바일은 한 열과 확인 단계의 펼쳐진 요약이다. 각 단계는 제목과 순서를 텍스트로 표시한다.

첫 구현에서 실제로 적용 가능한 built-in `riskProfile`과 기존 historical replay만 제공한다.
저장된 PortfolioPolicy를 선택해 실제 적용하는 흐름은 연결 전까지 지원 범위 설명으로 표시한다.
정책을 저장하거나 queued bucket test를 등록하는 기존 기능은 전략·정책 메뉴에서 계속 접근한다.

- 입력 가능한 값은 runner에 반영된 값만이다. 입력 유효성과 데이터 가용성은 별도 결과다.
- `dry_run_fixture`는 판단 provider다. 실제 시장 데이터와 합성 데이터의 분류와 혼동하지 않는다.
- 초기 생성 동선은 fixture decision provider만 사용하며 외부 AI 비용을 발생시키지 않는다.
- 비용/benchmark 선택은 실제 runner 전달 또는 명확한 미지원 거부 계약을 먼저 검증한다.
- 사용자 설정을 별도 고정값으로 조용히 대체하지 않는다. 요청값과 실제 적용값을 최종 단계에서 보여준다.
- 마지막 행동은 정확하게 ‘paper 실행 시작’ 또는 ‘테스트 대기 등록’이다. 둘을 같은 CTA로 쓰지 않는다.
- `accepted` 응답은 완료가 아니다. 반환된 batch ID 상세로 이동하고 아직 관측되지 않은 시간을 표시한다.
- 필드 오류·409 실행 중 충돌·401/403 권한 오류·네트워크 불확실성에도 값과 단계를 보존한다.
- 응답을 못 받았다고 생성 POST를 자동 반복하지 않는다. 멱등성 계약 전에는 상태 확인 안내를 보여준다.
- 지원하지 않는 취소·재개·자동 재시도·서버 초안 저장 버튼은 만들지 않는다.

### 3. 실행 워크스페이스

헤더는 실행 식별자, 저장된 상태, 실제 적용 설정, 관측 시각, paper-only 경계를 담는다.
실행 중에는 저장된 phase·처리 수/총량·heartbeat만 표시한다. 총량 없이 진행률을 만들지 않는다.

| 탭 | 주요 콘텐츠 | 자료가 없을 때 |
| --- | --- | --- |
| 요약 | 지표 3–4개, 자산 변화/낙폭, 비용·범위·표본 한계 | ‘미수집/미지원/누락’을 구분하고 0·빈 차트로 대체하지 않음 |
| 리플레이 | 시점 차트와 사건, 선택 시점 inspector | 필요한 시계열/사건 연결 전에는 비활성 이유와 기존 자료 경로 |
| 판단 근거 | 후보 → provider → deterministic Risk → 모의 체결 참조 | 연결되지 않은 사건을 같은 판단으로 추정하지 않음 |
| 기록 | 입력·버전·source·산출물·audit, 마지막에 raw JSON | source 오류를 실행 실패로 단정하지 않음 |

데스크톱 리플레이는 차트 65%/inspector 35%, 모바일은 선택 사건 전체 상세다.
색상만으로 성공·경고·차단을 구분하지 않는다. 원본을 바꾸는 ‘재실행’ 대신 지원 시
‘조건 복제 후 새 실험’을 제공하며 새로운 ID와 검증을 거친다.

## 비교의 최소 조건

성과 순위보다 자료 종류, source, 기간, universe, scope, provider, 비용, benchmark,
policy/code version의 차이를 먼저 보여준다. 값의 미관측은 동일함을 뜻하지 않는다.
같은 실행·누락 입력·다른 source/기간·full portfolio와 단일 bucket은 자동 동등 비교하지 않는다.
비교 불가와 참고 비교를 구분한다. 합성 결과를 실제시장 성능 증거처럼 표현하지 않는다.

## 기능 유지와 비범위

현재 Next와 legacy 기능 이전표는 [기술 설계](technical-design.md#기존-기능-이전표)에 둔다.
새 화면이 생겼다는 이유로 기존 page/API·artifact를 삭제하지 않는다. API unavailable, missing,
invalid, stale, incomplete, unsupported와 실제 숫자 0을 분리한다.

비범위: live trading, 외부 AI 유료 호출, 계정 설정 변경, Risk 우회, backend 전면 재작성,
PortfolioPolicy 실행 적용의 근거 없는 주장, shared allocator/원자 회계 통합, PR #788 재개,
EXP CLI를 별도 검증 없이 dashboard에 붙이기, 데이터 수집/삭제, 새로운 배포 환경 설정.
