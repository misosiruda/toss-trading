# UI writer-child identity follow-on

This UI companion includes the API writer-child lookup follow-on on top of the frozen API `3099348326e25a7d8899a3341ccfe290c4fc51c6`, and preserves the existing PR807 frontend from `ee691908bece97f552d71158f059973dc4d8a747`. API source, API tests and the API-owned `provenance-read-contract.md` are propagated unchanged. This companion adds only the frontend validator/adapter tests, the UI-owned writer integration and this UI contract to the existing PR807 scope.

The display adapter matches the API's additional admission of bounded canonical leading-hyphen writer children. Generic alphanumeric-first ASCII IDs and the256-character cap remain. Arbitrary leading-hyphen IDs, malformed padded/safe indexes or months, terminal line breaks, escapes and forbidden characters remain invalid. The adapter preserves the exact ID and encodes it once into the GET query. Invalid UI IDs cause no network read. Read-only partial observations do not restore original input, enable clone or establish comparability. Comparison identity syntax is a separate unchanged contract.

The API-owned fourteen-writer/twenty-eight-child HTTP matrix and six stored-sibling forbidden suffix classes remain in the API test. `apps/dashboard/tests/provenance-contract/writer-ui.test.mjs` is the UI-owned integration: the same fourteen actual synthetic writers create twenty-eight skipped children, the real local API serves each, and `readRunProvenance` calls that API and projects the real response. It preserves exact identity, transport query encoding, redaction and POST/runner/provider absence; invalid UI suffixes and overlength IDs do not reach fetch. No API test dynamically imports frontend source.

Run the root build first, then `node --test apps/dashboard/tests/provenance-contract/writer-ui.test.mjs` from the repository root. Normal frontend unit tests remain independently runnable through the dashboard script; this integration is deliberately outside their top-level glob. All fixtures are synthetic; no paid AI, live execution, credentials or real data are used. Linux full, Security and independent review remain separate from local Windows verification.
